Catch the leaks your AI pair-programmer left behind.

LaunchArmor is one Go binary that finds hardcoded API keys, open Supabase tables and risky code in apps built with Cursor, Bolt, v0 or Claude. Then it writes you a locked-down Linux deployment. Free, offline, no account.

$ curl -fsSL https://raw.githubusercontent.com/UltraDarshan/launcharmor/main/install.sh | bash

Linux and macOS, amd64 and arm64. Windows binaries are on the releases page.

One binary, four jobs

No runtime dependencies and nothing leaves your machine. Each command exits non-zero when it finds something serious, so it drops straight into CI.

Find secrets and risky code scan

  • CriticalOpenAI keys, incl. sk-proj
  • CriticalLive Stripe secret keys
  • CriticalSupabase service-role keys
  • CriticalSecrets in NEXT_PUBLIC_ / VITE_ vars
  • CriticalAnthropic, AWS and GitHub keys
  • CriticalFirebase rules open to everyone
  • HighCommitted .env files
  • HighDynamic code and shell execution
  • MediumWildcard CORS headers

Placeholders and public keys are skipped, and every secret is masked in the output so your CI logs stay clean.

Close open tables db-audit

Replays your Supabase migrations and finds tables with no Row Level Security, or with a policy that lets anyone edit every row. Prints SQL that fixes it.

Deploy on a sandboxed server harden

Writes a Caddyfile, a rate-limited Nginx config and a systemd unit with no capabilities, a read-only filesystem and a syscall allow-list.

systemd-analyze security 1.5 OK

Guard the edge for free

An optional Cloudflare Worker blocks probes for /.env and /.git, rate-limits each IP so bots can't drain your AI credits, and masks any API key that slips into a response.

Block bad deploys in GitHub Actions

Add one step to your workflow. Any critical or high finding, or a table without RLS, fails the build before it reaches production.

Read the Action docs
.github/workflows/ci.yml 
steps:
  - uses: actions/checkout@v4
  - name: LaunchArmor security audit
    uses: UltraDarshan/launcharmor@main
    with:
      audit_db: 'true'
